**本輪重點**：

1. **脫離已知 RCE 範圍**：Next 15.0.0 落在 React2Shell（App Router 未認證 RCE）受影響範圍；15.0.x 線修補版為 15.0.5，本次直接走 15.5 線。沒有任何原始碼因 React 19 型別需要修改。
2. **認證依賴汰換**：`pyjwt` 的 `decode` 明確指定 `algorithms`、要求 `exp`／`sub`；`argon2-cffi` 對不合法雜湊改回 `False`（原本 passlib 會丟例外）；`uv.lock` 移除 python-jose、passlib、ecdsa、rsa。
3. **Session 可撤銷**：access／refresh token 帶 `ver`，與 `users.token_version` 比對，不符 → `401 token revoked`；無 `ver` 的舊 token 視為 0，升級不登出使用者。
4. **改密碼不踢掉目前裝置**：同一筆 commit 遞增版本，回應新增 `access_token`／`token_type` 並重設 refresh cookie。
5. **修掉既有 bug**：前端原本從未呼叫 `/auth/refresh`，access token 15 分鐘到期就被踢回登入頁；現在 401 時 single-flight refresh＋重試一次。
6. **Webhook 不能打內網**：寫入時只收 http／https、拒絕 userinfo、私有／loopback 等 IP 字面值、`localhost`／`*.local`／`*.internal`、非標準 IPv4 寫法；送出時所有 DNS 結果都須為全域位址，並釘 IP 連線（`Host`／SNI 仍用原 hostname、不跟隨 redirect）。
7. **審查時找到第二個入口**：Web Push 訂閱 endpoint 也是使用者提供的 URL，同樣納管（pywebpush 自行建連線，無法釘 IP）。
8. **行為變更**：既有指向內網／localhost 的 webhook 會在下一次投遞被擋下（不刪資料、無 migration）；自架需要者設 `WEBHOOK_ALLOW_PRIVATE_HOSTS=true`。
9. **依賴不再靜默老化**：Dependabot（每週一、minor／patch 合併群組）＋CI `audit` job（尚未實跑）。

## 四、設計決策摘要

- **D1 Next 走 15.5 線，不跳 16**：目標 `next@15.5.29`；跳 major 的風險留給獨立 phase。`next.config.mjs` 的 `experimental.typedRoutes` 改頂層 `typedRoutes`。
- **D2 `python-jose` → `PyJWT`**：只用 HS256；`decode` 一律傳明確 `algorithms`；既有 token 格式相容。
- **D3 `passlib` → `argon2-cffi`**：既有 `$argon2id$` 雜湊直接驗證，無資料遷移；不合法雜湊回 `False`；dummy hash timing 防護保留。
- **D4 `users.token_version`（Migration 0028）**：`INTEGER NOT NULL DEFAULT 0`；token 的 `ver` 與使用者列比對，零額外查詢。
- **D5 舊 token 相容**：無 `ver` 視為 0。
- **D6 何時遞增**：改密碼（並重新簽發目前裝置 token）、`POST /api/auth/logout-all`；`/logout` 維持只清 cookie。
- **D7 不做 per-session refresh 表**：無 rotation 重用偵測、裝置清單、單一 session 撤銷。
- **D8 PAT 不受影響**：`ims_pat_` 有自己的刪除流程。
- **D9 Web 補上自動 refresh**：401（請求帶 token、路徑非 `/auth/*`）時 single-flight refresh 並重試一次；store token 已被更新則沿用，store 已清空不 refresh，重試後仍 401 才清 store。
- **D10 兩道檢查**：寫入時（不做 DNS，→ `422` `webhook_url_not_allowed`）與送出時（解析 DNS，全部結果須為全域位址；失敗記 delivery，`status_code=NULL`、excerpt `error: destination not allowed`）。
- **D11 釘住解析結果**：連到已驗證 IP，`Host`／SNI／憑證驗證用原 hostname；`follow_redirects=False`、`trust_env=False`；最多試 3 個位址。
- **D12 自架 opt-in**：`WEBHOOK_ALLOW_PRIVATE_HOSTS`（預設 false）。
- **D13 既有資料**：不 migration、不刪既有 webhook。
- **D14 CI**：`dependabot.yml`＋`audit` job（會失敗的 gate）。
- **D15 Web Push endpoint 納管**：要求 `https`、同一個 guard、送出前同步解析、`max_redirects=0`；無法釘 IP。
- **D16 `::/96`**：`is_global` 會把 `::7f00:1` 判為全域位址，與 NAT64／6to4／Teredo 一併封鎖。

## 五、已知限制

- **`/logout` 後 access token 最長仍可用 15 分鐘**：沒有 per-session 撤銷與裝置清單。
- **access token 仍存 `localStorage`、無 CSP**：排入 Phase 46。
- **`pnpm lint` 無法執行**：repo 從未有 ESLint 設定檔（`next lint` 卡在互動式設定提示），為既有缺口；CI 的 lint 步驟在非互動環境應也會失敗，排入 Phase 46。
- **e2e 有 1 個情境 skip**：`locations-tree.spec.ts` 的「真實遷移後的位置樹」依賴舊 dev 庫的 `phase26_demo` 遷移 fixture，全新資料庫不存在 → 改為明確 skip（原本會登入逾時失敗；與本期無關）。其餘 chromium 91 情境與 ai-stub 4 情境全數通過（含新增的 `session-security.spec.ts` 與改寫的 `webhooks.spec.ts`）。
- **CI `audit` job 未實跑**：首次執行可能因既有漏洞紅燈。
- **peer 警告**（升級前就存在）：`next-intl@3.21.1`、`next-themes@0.3.0` 未宣告支援 React 19／Next 15；`next@15.5.29` 要 `@playwright/test ^1.51.1`（目前 1.48.0）。
- **`JWT_SECRET` 長度**：正式環境少於 32 bytes 時 PyJWT 發 warning（仍可運作）；dev 預設 secret 為 30 bytes 會觸發。建議 `openssl rand -hex 32`。
- **Web Push 無法釘 IP**：對 DNS rebinding 只有降低；回應不回傳使用者（blind）。
- **Webhook 回應本文**：仍整份讀入後才截 500 字（未做串流上限）。
- **版本遞增非原子**：ORM 讀取後加 1，並行時可能只加一次，安全效果相同。
- **PAT 可呼叫 `/logout-all` 與改密碼**（改密碼仍須舊密碼），延續「PAT 等同使用者權限」的既有設計。
- **既有內網 webhook 會被擋**：下一次投遞留下失敗紀錄；需要者設 `WEBHOOK_ALLOW_PRIVATE_HOSTS=true`。
- **首次 push 後 CI 尚未確認**：`main` 已 push，但 CI 從未在 Phase 22 之後的 commit 上跑過；`web` job 的 lint 步驟預期失敗（無 ESLint 設定），新的 `audit` job 也可能因既有漏洞紅燈。
