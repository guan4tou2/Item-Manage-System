**本輪重點**：

1. **查詢台馬上有真實資料**：Phase 39 只有 5 種 action，現在登入、刪物品、發權杖、改密碼都看得到。
2. **登入失敗不會變成新的洪水面**：陌生帳號完全不寫；既有帳號每 10 分鐘最多 1 列；對外一律 `401 invalid credentials`。
3. **敏感值硬規則**：PAT 原文／雜湊、密碼明文／雜湊一律不進 `meta`；測試直接拿 token 原文比對整列序列化結果。
4. **標籤 PDF 自帶字型**：reportlab CID 字型不嵌入，實測 PDFium 對「舊、電、風、臺、灣、櫃」等繁中字直接缺字 → 內附 Noto Sans TC 子集（OFL 1.1），PDF 只嵌用到的字形（約 20 KB／份）。
5. **真值解碼延伸到 PDF**：`pypdfium2` raster 後用 `zxing-cpp` 解 QR 與 Code128，另斷言 `/FontFile2`（字型確實內嵌）、A4 尺寸與頁數。
6. **附帶修掉一個既有顯示 bug**：批量標籤預覽卡片固定 `4cm` 高，內容遠超高度 → 名稱／短 id 被 flex 壓成 0 高度；改 `min-h-[4cm]` 後恢復可見（列印仍 6 cm 寬）。
7. **兩套報表、一條管線**：週報沒有複製月報的資料表、payload、通知型別或 Email 管線，只多一個 job 與 `kind`；指標口徑完全一致，避免兩套解釋。
8. **週報預設關閉**：新的主動寄送不應對既有使用者預設開啟；`report_weekly_enabled=false`，設定頁明示 opt-in。空週仍留一列（可在 `/reports` 看到），但不通知、不寄信。
9. **混合週／月 key 的排序**：`2026-W42` 與 `2026-09` 的字典序不是時間序 → 清單改以 `generated_at DESC`；API 測試驗證混合資料的新到舊順序，e2e 驗證週報卡與日期範圍。
10. **附帶修掉月報 stale 誤判**：原本固定 26 小時，導致每月 2 日起月報永遠顯示「停跑」；改 per-job 門檻（26／170／770 小時）並補邊界測試。
11. **Migration 驗證策略調整**：既有 migration 0021 的 constraint ALTER 在 SQLite 會直接 `NotImplementedError`，因此 0026 的 up/down 改在獨立 PostgreSQL 容器實測；SQLite 測試以 `create_all` 覆蓋新 schema，不用 migration 硬跑。
12. **登入防護只計失敗**：`slowapi` 會在密碼驗證前計數，成功登入與 NAT 共享 IP 容易被誤鎖；改在 `InvalidCredentials` 之後才寫入，成功登入不計數並清除帳號紀錄。
13. **帳號＋IP 雙軌**：帳號分級 5／15 分、10／1 時、15／24 時；IP 分級 10／1 分、30／15 分。被封鎖的請求不再寫入，避免攻擊者無限延長受害者鎖定。
14. **不列舉帳號**：未知帳號也走同一條計數與鎖定路徑，對外一律 `429 too many login attempts`＋`Retry-After`；既有的 `401 invalid credentials` 不變。
15. **隱私**：`login_attempts` 只存 `HMAC-SHA256(jwt_secret, "kind:value")`，不保存原始 username／IP；每次失敗清理 24 小時前紀錄。
16. **Timing 防護**：未知帳號仍對固定 dummy Argon2 hash 驗一次密碼，降低「帳號是否存在」的回應時間差。
17. **Proxy headers 真的生效**：compose 原本的折行命令讓 shell 把 `--proxy-headers` 當成獨立命令，uvicorn 子程序根本沒收到旗標；改單行並以 `/proc/1/cmdline`、live log 驗證 `request.client.host` 是 nginx 轉來的來源。
18. **Fail-soft**：節流查詢／寫入／重置失敗只 log warning＋rollback，不讓登入回 500；代價是 DB 異常時暫時 fail-open，已列入已知限制。

## 四、設計決策摘要

- **D3 登入失敗防洪水**：`audit_service.log_login_failure()` 先查 `action="auth.login_failed" AND resource_id=<user.id> AND created_at >= now-10min`；有就跳過。查詢失敗寧可不寫（不影響登入）。不引入 Redis／記憶體計數（多 worker 不共享）。
- **只記既有帳號**：登入失敗後才查一次使用者；陌生帳號不寫稽核（避免匿名灌寫與列舉訊號）。
- **D5 交易順序**：`audit_service.log()` 會 commit（既有 fail-soft）。新呼叫點一律在主寫入 commit 之後；物品／權杖稽核放在 webhook dispatch 之前（避免等外部 HTTP）。
- **D6 批次刪除**：一次 API 呼叫只寫 1 列 `item.bulk_deleted`，`meta={"count", "item_ids"}`；不逐筆寫、不記 names。
- **D7 `backup.export` 不納入**：本人匯出自己的資料、頻率高；異常量體屬告警功能。
- **D8 UI 零改動**：facets 由資料庫動態產生；e2e 只加 1 個斷言證明 `auth.login` 自動出現。
- **D9 標籤 PDF 全有全無**：任一 id 不存在／已軟刪／非本人 → 404，不默默跳過（避免使用者拿到少幾張卻不知道）；ids 去重後 1–100 筆。
- **D10 固定 21 格版面**：A4 3×7、63.5×38.1 mm、左右 9.75 mm／上下 15.15 mm、欄列距 0；`start=0..20` 跳過前 N 格以重用部分貼紙；不做版型自訂。
- **D11 內嵌 Noto Sans TC**：CID 字型不嵌入且實測缺繁中字 → 內附 OFL 字型子集（6.6 MB）；PDF 只嵌實際字形（約 20 KB／份）。reportlab 5.x 內建 barcode widget API 不穩定 → QR 用既有 `qrcode`、Code128 用 `python-barcode`。
- **D12 PDF 真值驗證**：`pypdfium2` raster＋`zxing-cpp` 解碼 QR／Code128；`/FontFile2` 斷言字型內嵌；避免「圖有出來但掃不到」的假綠。
- **D13 同一張表＋`kind`**：週報／月報共用 `reports`，`period` 放寬到 10、`kind` 預設 `monthly`；`UNIQUE(user_id, period)` 因兩種 key 格式不重疊而仍成立。Migration 0026 的 downgrade 會**先刪除週報列**再縮回 7（destructive）。
- **D14 ISO 週**：`previous_week(today)` 以「本週一 − 7 天」計算，key 取該週一的 `isocalendar()`；週一執行生成前一週，週間補跑仍取最近一個已結束的完整週，避免跨年與「當週未結束」歧義。
- **D15 週報 opt-in**：`report_weekly_enabled` 預設 **false**。這是新的主動寄送，不應對既有使用者預設開啟；設定頁明示「每週摘要」。
- **D16 指標口徑完全重用**：週報只換 `Period`，`build_payload` 不動；到期視窗仍為期末後 30 天，「目前庫存」仍是生成當下快照，不假裝是週日 24:00 的歷史快照。
- **D17 清單排序**：`YYYY-MM` 與 `YYYY-Www` 的字典序不是時間序 → `GET /api/reports` 改 `generated_at DESC`（同時間再以 id）；limit／offset／total 不變。
- **D18 per-job stale**：`JobSpec.stale_after_hours`（預設 26）；`expiry-scan` 26h、`report.weekly` 170h、`report.monthly` 770h。`GET /api/jobs/{name}/status` 回傳對應門檻，修正月報每月 2 日後誤判停跑。
- **D19 API additive、Web 重用**：`ReportRead.kind`／`ReportPayload.kind`／偏好新欄位皆為 additive，payload version 維持 1；不新增端點、不做 `?kind=` 篩選。Web 清單以「週報」徽章＋日期範圍區分，詳情依 `payload.kind` 換文案，設定頁兩個獨立開關。
- **D20 e2e 用真實 job**：開啟「每週摘要」→ psql 回填物品 `created_at` 到上週 → 管理員觸發 `report.weekly` → 清單／詳情／通知 deep link → 重跑冪等；不 mock job。
- **D21 Migration 驗證**：0026 在獨立 PostgreSQL 容器實測 up → down → up；SQLite 因既有 0021 的 constraint ALTER 直接 `NotImplementedError`，只以 `create_all` 覆蓋新 schema。
- **D22 只計失敗**：`slowapi` 以請求數計數，成功登入也會被算進去，且 route decorator 難以用 body 的 username 當 key；本 phase 改在 `InvalidCredentials` 後寫入 `login_attempts`，成功登入不計數並清除帳號紀錄。
- **D23 帳號分級**：5 次／15 分→15 分、10 次／1 時→30 分、15 次／24 時→1 時。以 `username.strip()` 精確比對（不大寫折疊，避免誤鎖大小寫不同的另一個帳號）；第 5 次失敗仍回 401，第 6 次起 429。鎖定從時間窗內**最新一次失敗**起算，避免慢速噴射因第 N 新太舊而提前解鎖。
- **D24 IP 分級**：10 次／1 分→1 分、30 次／15 分→15 分。Key 為 `request.client.host`；成功登入不清 IP，否則攻擊者可用已知密碼的帳號反覆重置。
- **D25 封鎖不寫入**：被鎖的請求直接 429，不再新增失敗列；否則攻擊者可持續把 `locked_until` 往後推，讓受害者永遠解不開。
- **D26 不列舉帳號**：未知帳號也計數、也鎖定；對外一律 `429 too many login attempts`＋`Retry-After`，既有錯誤仍 `401 invalid credentials`。被封鎖時不執行密碼驗證。
- **D27 隱私與清理**：`key_hash = HMAC-SHA256(jwt_secret, "kind:value")`，不存原始 username／IP；每次失敗刪除 24 小時前紀錄，避免表無限成長。JWT secret 輪替會讓舊計數失效（可接受）。
- **D28 Timing**：未知帳號仍對固定 dummy Argon2 hash 驗一次密碼，降低帳號列舉的時間差；仍回同一個 401。
- **D29 Fail-soft**：節流查詢／寫入／重置失敗只 log warning＋rollback，不讓登入回 500；代價是 DB 異常時暫時 fail-open。DB 正常時登入本身仍會失敗。
- **D30 Proxy 信任**：compose 的 API 只 `expose` 給 nginx；uvicorn 加 `--proxy-headers --forwarded-allow-ips='*'` 取真實 IP。若直接暴露 API，必須移除旗標或限制 proxy IP。**實作時發現**原本折行命令讓 shell 把旗標當獨立命令，uvicorn 沒收到；改單行後以 `/proc/1/cmdline`、live log 驗證。
- **D31 e2e 真實鎖定**：連續 5 次錯密碼→第 6 次顯示「嘗試次數過多」，鎖定期間正確密碼也被拒絕；不用 mock API。

## 五、已知限制

- **帳號鎖定可被用來 DoS**：攻擊者可刻意用錯密碼鎖住已知帳號；第一級只 15 分鐘、最長 1 小時，且被封鎖的請求不延長鎖定；仍有短暫影響。
- **共享 IP 可能被誤鎖**：NAT／辦公室使用者合計 10 次失敗/1 分會被鎖 1 分鐘、30 次/15 分會被鎖 15 分鐘；成功登入不受影響，但尖峰時段仍可能感受到。
- **Fail-open**：節流查詢或寫入失敗時 log warning 後放行；DB 異常期間暫時沒有防護。DB 正常時登入本身仍會失敗。
- **無 CAPTCHA／MFA**：本 phase 只做頻率與鎖定，不處理自動化 CAPTCHA、MFA／WebAuthn、註冊／refresh／忘記密碼端點。
- **密碼噴射仍可能繞過**：攻擊者若持續更換來源 IP，IP 分級只能減緩；帳號分級仍會保護單一帳號，但跨帳號的大量嘗試需 WAF／上游防護。
- **Proxy headers 信任邊界**：`--forwarded-allow-ips='*'` 只在 API 不直接對外、且 nginx 會覆寫 `X-Forwarded-For` 時安全；直接暴露 API 時必須改掉。
- **稽核不含 IP／User-Agent**：`audit_logs` 無此欄位（避免本 phase 引入 migration）；`login_attempts` 也只存 HMAC，不存原始 IP。未來若要做來源分析需另開 phase。
- **匿名失敗嘗試不可見**：陌生帳號的登入失敗不寫稽核（隱私／防灌寫的取捨）；若需要「攻擊量」指標，應走 metrics／告警而非稽核列。
- **`auth.login` 每次登入寫 1 列**：目前規模可接受；若未來有高頻服務帳號，再考慮只記首次或抽樣。
- **標籤 PDF 版型固定**：不做尺寸／欄數自訂，也不支援位置標籤 PDF；`start` 未暴露在 UI（需直接打 API），未來有需求再加。
- **字型覆蓋邊界**：Noto Sans TC 未涵蓋部分日文新字體漢字（如「収」）與 emoji，會顯示缺字框；一般繁中／簡中／假名／拉丁皆已驗證。
- **PDF 同步產生**：上限 100 張；若未來要一次數千張，需改非同步 job。
- **週報預設關閉**：使用者必須在 `/settings/reports` 開啟「每週摘要」才會收到；這是刻意的 opt-in，不是漏寄。
- **週報不提供 backfill／自訂期間**：job 永遠取最近一個已結束的完整 ISO 週；漏跑多週只會補「最近一週」，更早的週不另外補。
- **週報沿用月報口徑**：到期視窗仍是期末後 30 天，沒有「只看到期 7 天」的專屬口徑；「目前庫存」是生成當下快照。
- **清單無 kind 篩選**：週報與月報混合顯示，只以徽章與日期範圍區分；資料量變大再加 tabs／`?kind=`。
- **Migration 0026 downgrade 是破壞性的**：會刪除所有 `kind='weekly'` 的列；降級前請先備份。
- **SQLite 未驗證 0026／0027 migration up/down**：既有 0021 在 SQLite 的 constraint ALTER 會直接失敗；新 schema 由 `create_all` 覆蓋，migration 只在 PostgreSQL 實測。
- **Migration 0027 downgrade 會刪除節流紀錄**：只影響 `login_attempts`，不影響使用者或物品；降級後所有鎖定狀態重置。
