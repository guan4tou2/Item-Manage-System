# Phase 49：批次成本

- **狀態**：🚧 進行中
- **日期**：2026-11-14
- **基線**：`main` `d3e258e`（Phase 47）；本期於獨立分支進行，與 Phase 48（Migration 0030）平行，合併時接在其後
- **來源**：roadmap 候選「批次成本（per-batch cost）」；Phase 27（成本與估值）與 Phase 22（批次庫存）的延伸

---

## 現況與問題

`items.cost` 是物品層級的單一單價，估值一律 `cost × quantity`。啟用批次管理（`track_batches`）的物品，不同批次常以不同價格購入（特價、漲價），目前只能填一個價格，估值會失真。

## 目標

批次可以各自記錄單位成本；估值、統計與報表在有批次成本時使用它，沒有時退回物品層級的單價。

---

## 設計決策

### 資料

- **D1 `item_batches.unit_cost`（Migration 0031，接在 0030 之後）**：`NUMERIC(12,2)`、nullable、`>= 0`（check constraint）。downgrade 刪欄。
- **D2 有效單價**：批次的有效單價＝`batch.unit_cost`，為 null 時退回 `item.cost`；兩者皆 null → 該批次「未定價」。`items.cost` 的定位變成「預設單價」。
- **D3 物品的估值**（單一定義，統計與報表共用同一個運算式）：
  - 未啟用批次：`item.cost × item.quantity`（不變）。
  - 啟用批次：`Σ 未耗盡批次（quantity × 有效單價）`；未定價批次以 0 計。
- **D4 「未定價」的物品數**（估值頁的未填比例）：未啟用批次 → `cost` 為 null；啟用批次 → **有任何**未耗盡批次未定價。沒有任何未耗盡批次的批次物品（數量 0）不算未定價。
- **D5 幣別**：沿用帳號層級的 `currency` 偏好（Phase 27），批次不另存幣別。

### API（全部 additive）

- **D6**：`BatchCreate`／`BatchUpdate`／`BatchRead` 新增 `unit_cost`（驗證規則沿用 `items.cost` 的 `COST_FIELD`：非負、最多 2 位小數）。`BatchUpdate` 要能區分未提供與明確設為 null（清除）。不新增端點。
- **D7 統計**：`GET /api/stats/value` 的總值、未定價數與三個分布（分類／位置／倉庫）改用 D3／D4。回應結構不變。
- **D8 報表（月報／週報）**：期末估值改用 D3。期初估值是由期末值反推（扣掉期間內的數量異動），異動量的計價改用「目前的加權平均單價」＝該物品 D3 估值 ÷ 目前數量；數量為 0 時退回 `item.cost`。這是近似值（既有做法本來就以「目前單價」反推），文件明示。payload 結構與 `version` 不變。
- **D9 備份**：匯出的批次列加上 `unit_cost`，匯入時還原；舊備份沒有此欄位照常匯入。`format_version` 不變。
- **D10 不受影響的流程**：FEFO 消耗、盤點調整、停用批次管理都只動數量，不需要動成本欄位；批次耗盡後不再計入估值。CSV 匯入／匯出只處理物品層級，不含批次（維持現狀）。

### 介面

- **D11 新增／編輯批次的對話框**：加一個選填的「單位成本」欄位，顯示帳號的幣別符號；留白＝使用物品的預設單價，欄位下方用一行說明這件事（有預設單價時顯示其金額）。
- **D12 批次列**：有批次成本時在列上顯示單價（`formatCurrency`、`tabular-nums`）；沒有時不顯示（不重複顯示預設單價，避免雜訊）。
- **D13 物品表單的成本欄位**：物品啟用批次管理時，欄位標籤旁補一句「批次未填成本時使用此值」。
- **D14 物品詳情**：啟用批次且有任何批次成本時，在批次區塊標題旁顯示該物品的估值小計（依 D3，在前端由批次資料計算，與統計頁一致）。
- **D15 狀態與權限**：沿用既有批次區塊的 LOADING／EMPTY／ERROR 呈現；viewer 唯讀、不渲染編輯入口（既有行為）。成本輸入錯誤（負數、超過 2 位小數）在欄位下方即時提示，並擋下送出。
- **D16 視覺**：金額是中性資訊，不用飽和色；一律走既有 token。
- **D17 i18n**：zh-TW／en 同步。

## 明確不在本期範圍

- 批次層級的幣別與匯率
- CSV 匯入／匯出批次
- 收據辨識入庫時自動建立帶成本的批次

## 實作結果

### 實際完成項目

- D1–D10：新增 nullable `NUMERIC(12,2)` 批次成本、非負 check constraint 與 Migration 0031（接 0030）；schema 沿用 `COST_FIELD`，PATCH 區分省略與 null。統計與報表共用 `repositories/valuation.py` 的 D3／D4 SQL 定義，備份還原相容舊檔，維持既有版本。
- 報表以目前加權平均單價反推期初；數量為 0 時退回物品預設單價。這仍是依目前庫存與價格推估的近似值，不代表歷史成本或 FIFO 成本法。
- D11–D17：批次新增／編輯成本欄、幣別與預設值提示、即時驗證、列單價、估值小計、物品預設單價提示、雙語文案；沿用既有 UI 元件與 token。估值純函式以整數分計算，避免浮點累加誤差。
- 新增 API／Web 回歸測試，以及既有批次到期 spec 內的跨批次成本 e2e（包含編輯、統計對帳及 375px 溢出斷言）。OpenAPI 與 TS 型別已由本 worktree 重新產生。

### 與計畫的差異

- 既有批次介面實際只有新增對話框；本期以共用對話框補齊編輯入口。既有 ERROR 狀態會誤顯示空清單，已補上區塊內錯誤與重試，符合 D15。
- 停用追蹤的既有確認文案補上批次成本也會刪除，對齊原本刪除批次列的行為；未新增確認步驟。
- 無資料定義、端點、版本或 Migration 串接決策變更。
