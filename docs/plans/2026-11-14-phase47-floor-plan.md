# Phase 47：樓層平面圖互動

- **狀態**：✅ 完成
- **日期**：2026-11-14
- **基線**：`main` `f9997d2`（Phase 46）；API 1440 passed、Web 805 passed（135 檔）、e2e 30 spec／96 情境、Migration `0028 (head)`
- **來源**：roadmap 候選「樓層平面圖互動」

---

## 現況

`locations.floor_plan_image_id` 自 Phase 11 起存在於 API（model／schema／PATCH 可寫），但**前端沒有任何平面圖介面**：無法上傳、看不到圖、也沒有熱區資料。本期把它做成可用的功能。

## 目標

在某個位置（典型是樓層）上放一張平面圖，把它的**直接子位置**（房間、櫃子）標成圖上的區域；點區域就看到那個位置的物品。

1. 上傳／更換／移除位置的平面圖。
2. 在圖上為子位置畫矩形區域。
3. 檢視模式：點區域 → 該位置（含子孫）的物品清單。
4. viewer 可看、可點，不可編輯。

---

## 設計決策

### 資料

- **D1 區域存在子位置上**：`locations.plan_region`（JSON、nullable；Migration 0029）＝「這個位置在**父位置平面圖**上的區域」。一對一、隨位置搬移／刪除，不另開資料表。
- **D2 正規化矩形**：`{"x","y","w","h"}`，皆為 0–1 的浮點數，相對於圖片寬高（與解析度、顯示尺寸無關）。只支援矩形（不做多邊形）。限制：`0 ≤ x,y`、`w,h ≥ 0.02`、`x+w ≤ 1`、`y+h ≤ 1`；儲存時四捨五入到小數 4 位。不合格 → `422`。
- **D3 一致性規則**（伺服器端強制）：
  - 設定 `plan_region` 時，該位置必須有父位置，且父位置有 `floor_plan_image_id`；否則 `422 {"code":"parent_has_no_floor_plan"}`。
  - 位置**搬到別的父位置**（`parent_id` 改變）→ 自動清除它的 `plan_region`（區域是相對於舊父位置的圖）。
  - 父位置**移除**平面圖（`floor_plan_image_id` 設為 null）→ 清除所有直接子位置的 `plan_region`。
  - 父位置**更換**平面圖（設為另一張圖）→ **保留**子位置區域（常見情境是換一張更清楚的同一張圖）；UI 提示可能需要調整。
- **D4 圖片必須是自己的**：設定 `floor_plan_image_id` 時驗證該圖片存在且 `owner_id` 為本人，否則 `422 {"code":"invalid_floor_plan_image"}`（原本完全不驗證）。
- **D5 API 只做 additive**：`LocationRead`／`LocationTreeNode`／`LocationUpdate` 新增 `plan_region`；`LocationCreate` 不加（新位置建立後再畫）。沿用既有 `PATCH /api/locations/{id}`，**不新增端點**——檢視頁所需資料（子位置、區域、物品數）全部來自既有的 `GET /api/locations/tree`。
- **D6 備份**：匯出的位置列加上 `plan_region`；匯入時若有就還原（不合格的值略過並記 warning）。`format_version` 不變（新增的是選填欄位）。備份本來就不含圖片檔，還原到新環境後需重新上傳平面圖，區域會在圖片補上後重新出現。

### 介面

- **D7 獨立頁面** `/locations/{id}/plan`（不塞進位置樹）：樹節點的更多操作選單加「平面圖」；已有平面圖的節點在列上顯示一個地圖圖示按鈕（直接進入）。
- **D8 檢視模式（預設）**：
  - 圖片等比縮放至容器寬；區域疊在圖上，每個區域是一個**連結**（`<a href="/items?location={id}">`），標籤為「名稱＋物品數」。
  - 物品數＝該子位置**含子孫**的總數（由樹的直接物品數在前端加總），與點進去看到的清單一致。
  - 圖下方一律附**子位置清單**（名稱、物品數、連結）：作為小區域與螢幕閱讀器的等價入口，也列出尚未放置區域的子位置。
- **D9 編輯模式**（writer 才看得到切換鈕）：
  - 從清單選一個子位置 → 在圖上拖曳畫出矩形（pointer events，滑鼠與觸控共用）；已有區域時重畫即取代。
  - 選取的區域可用鍵盤調整：方向鍵移動、`Shift`＋方向鍵改變大小（每次 1%），`Delete`／`Backspace` 清除。
  - 每次變更立即 `PATCH`（樂觀更新，失敗回滾並 toast）；另有「清除區域」按鈕。
  - 編輯中圖片容器 `touch-action: none`（避免拖曳變成捲動）；離開編輯模式恢復。
- **D10 平面圖管理**：上傳（沿用 `POST /api/images`，既有 10 MB／MIME 限制）、更換、移除（AlertDialog 確認，說明會清除所有區域）。
- **D11 互動狀態表**（roadmap §5.4）：

  | 狀態 | 呈現 |
  |------|------|
  | LOADING | 圖片區 skeleton（固定比例佔位，避免版面跳動）＋清單 skeleton |
  | EMPTY：沒有平面圖 | writer：說明＋「上傳平面圖」主動作；viewer：「尚未設定平面圖」 |
  | EMPTY：沒有子位置 | 顯示圖片，提示「先新增子位置才能標示區域」＋回位置樹的連結 |
  | EMPTY：有子位置但都沒畫 | 檢視模式提示「尚未標示任何區域」；writer 附「開始標示」 |
  | ERROR：樹／圖片載入失敗 | 錯誤說明＋重試；清單仍可用（若樹已載入） |
  | ERROR：位置不存在 | 404 說明＋回位置樹 |
  | SUCCESS | 儲存不另外 toast（樂觀更新即回饋）；失敗才 toast |

- **D12 視覺**（依 `DESIGN.md`）：區域是連結，所以用 primary——1.5px primary 邊框＋primary 低透明度底（約 10%），hover／focus 加深並顯示 focus ring；標籤為 `text-xs`／600、物品數 `tabular-nums`。編輯中被選取的區域用實線加粗，其餘降為 muted 邊框。不用其他飽和色、不加陰影與動畫。色彩一律走既有 token，不硬編色碼。
- **D13 無障礙**：區域連結的 `aria-label` 為「{名稱}，{n} 件物品」；圖片有 `alt`；區域在 tab 順序中依子位置排序；觸控目標不足 44px 的小區域由下方清單補足。
- **D14 i18n**：zh-TW／en 同步。

## 明確不在本期範圍

- 多邊形／旋轉區域、區域重疊檢查
- 圖上直接顯示個別物品的圖釘
- 平面圖的縮放／平移手勢（依賴瀏覽器原生縮放）
- 從物品清單反查「在平面圖上的位置」
- 巢狀平面圖的導覽（房間自己也可以有平面圖，但不做「點房間再進到房間的圖」的串接）

## 實作結果

### 實際完成

- Migration `0029` 新增 nullable JSON `locations.plan_region`，downgrade 刪欄；model 沿用跨後端 `JSONType`。
- `PlanRegion` 明確驗證四欄、數值型別、最小尺寸及邊界，儲存至小數 4 位；PATCH 區分未提供與明確 null。清單與樹皆回傳區域。
- API 強制 D3 四條一致性規則與 D4 圖片擁有者驗證（建立位置的既有圖片欄位亦驗證）。保留原有搬移、循環與重名檢查。
- 備份匯出與 id-map 重建還原區域；不合格值略過並記 warning，舊格式與 `format_version` 維持相容。還原不含圖片檔，待重新上傳圖片後顯示區域。
- 重新匯出 OpenAPI 並產生 `packages/api-types`。
- 新增 `/locations/{id}/plan`：檢視／編輯、上傳／更換／確認移除、pointer 拖曳、鍵盤位移與縮放、清除區域；圖片沿用 Bearer blob URL 與自然比例。
- 區域使用 Next Link 與數字 `location` query，清單及區域標示含子孫物品總數；未放置子位置仍提供清單連結。viewer 不渲染任何編輯入口。
- 樹選單新增平面圖入口，有圖的節點新增具 aria-label 的地圖連結；`/locations/:path*` 已在 middleware 保護範圍，無需修改。
- 使用既有 UI 元件與語意 token，同步 zh-TW／en；補齊載入、空資料、找不到位置、樹／圖片失敗重試等狀態。
- 新增 API、純函式、元件、樂觀快取／回滾測試；新增三個 Playwright 情境（區域導覽、拖曳持久化與 375px 溢出檢查、viewer）。

### 與計畫的差異與實作取捨

- 設定／清除區域與設定／移除圖片共用 `useUpdateFloorPlan` mutation，統一同步樹及清單快取並於失敗回滾；請求期間阻止重複編輯，避免舊結果覆蓋新操作。
- 四欄各自四捨五入可能使矩形超界 0.0001，因此儲存前將右／下邊界向圖片內夾限，確保還原及回應仍可通過同一驗證。
- D4 使原有「直接寫入不存在 UUID」成功測試不再合法；僅更新該案例的圖片前置資料，保留成功斷言。
- `AuthImage` 增加圖片解碼錯誤 fallback，維持既有 props 相容；不另建圖片抓取流程。
- 未新增端點、套件或其他文件；未 commit／push／更動分支。

### 主代理的審查與實際操作

本機 Docker 未啟動，改以不依賴 Docker 的方式實測：API 以 SQLite 暫時資料庫（`create_all`）在本機啟動，Web 以 `next dev` 指向它，用瀏覽器走完主要路徑。

- **檢視**：平面圖與區域正確呈現；區域標籤的物品數為含子孫加總（廚房 2 件＝廚房 1＋上櫃 1）；點區域落在 `/items?location={id}`，清單內容與數字一致。
- **編輯**：選取子位置後以滑鼠拖曳畫出區域，立即儲存；重新載入後仍在。
- **手機寬度（375px）**：無水平溢出；清單連結高度 44px；區域可點。
- **入口**：位置樹上有平面圖的節點出現地圖連結；瀏覽器 console 無錯誤。
- **API 負向檢查**（實際請求）：孫位置設定區域 → `422 parent_has_no_floor_plan`；超出邊界 → `422`。

實測中發現並修正的三個問題：

1. **頁面水平溢出**：隱藏的檔案輸入用了 `Input` 元件（自帶 `w-full`），與 `sr-only` 疊加後撐出水平捲軸 → 改用原生 `<input>`。
2. **區域標籤不易閱讀且位置不一致**：標籤直接疊在圖上、沒有底色，編輯模式又變成置中而蓋到圖上的文字 → 一律靠左上，加上不透明底的標籤（`bg-background`／`text-foreground`），任何圖片上都讀得到。
3. **編輯時要來回捲動**：子位置的選取鈕原本在圖片下方的清單裡 → 編輯模式改在圖片正上方顯示選取列（accessible name 不變），清單只留「清除區域」。

另調整一條規則：搬移位置時若同一個請求**明確給了新的區域**（且新父位置有平面圖），保留該區域；只有未提供時才自動清除。
